# ADR 003: Article bodies are compressed files on disk, indexed in SQLite

## Context and Problem Statement

Quillfeed keeps every article it fetches so that the reader works offline from the feed's host, and so that search covers articles the feed has since dropped. An article is a few fields (title, link, author, dates) and a body of HTML, from 1 KB to several megabytes. Everything else Quillfeed stores is in the SQLite database (ADR 001). Where do article bodies go?

## Decision Drivers

- The database stays small enough to copy while Quillfeed runs.
- Reading one article is one lookup.
- A host with a small disk can cap how much Quillfeed keeps.

## Considered Options

1. Bodies as zstd-compressed files on disk, with one row per article in SQLite that holds the fields and the file's name
2. Bodies as BLOB columns in the SQLite database
3. Bodies in an S3-compatible object store

## Decision Outcome

Chosen: option 1, because it alone keeps the database small. With the maintainer's 2,400 feeds, a year of bodies as BLOBs made a 41 GB database that took 19 minutes to copy; with bodies as files, the database was 310 MB and copied in 9 seconds. Option 3 lost because it adds a service the host must run, against ADR 001's drivers. How it works is in [doc/design/storage.md](../design/storage.md).

Confidence: high that it works; the maintainer's instance has run this way since April. Medium that it is better than option 2 for a small instance, where the database would stay small either way.

### Consequences

- Good, because the database copies in seconds, so a backup can run every hour.
- Good, because a host can free space by deleting old body files, and Quillfeed shows those articles as "body no longer kept".
- Bad, because a backup is now two things, the database and the bodies folder, and they can be copied at different moments, leaving rows whose file is missing.
- Bad, because nothing makes a row and its file change together: a crash between writing the file and the row leaves a file no row names.

### Confirmation

Nothing checks that bodies stay out of the database. `tests/test_store.py` checks only that a body's file goes in a folder named for the first two characters of its name and ends in `.zst`.
