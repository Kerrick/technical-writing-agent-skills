# ADR 001: Quillfeed is one process with an embedded SQLite database

## Context and Problem Statement

Quillfeed is for one household, hosted by someone who is not an operator by trade, often on a small computer at home. How many moving parts does a deployment have?

## Decision Drivers

- Installing and upgrading is one step.
- A backup is something the host can do without reading documentation.

## Considered Options

1. One process, with SQLite in the same process
2. A web process and a worker process, sharing PostgreSQL
3. One process, with PostgreSQL beside it

## Decision Outcome

Chosen: option 1, because it is the only one where an upgrade replaces one program and a backup copies one folder. Options 2 and 3 lost because each adds a database server the host must install, upgrade, and back up.

Confidence: high that it works for a household: the maintainer's own instance holds 2,400 feeds. Low that it would hold for hundreds of readers, which nobody has tried.

### Consequences

- Good, because the host runs and upgrades one program.
- Bad, because fetching and serving share one process, so a fetch that uses all its memory takes the reader down with it.
- Bad, because a move to several processes later would mean replacing SQLite or putting a server in front of it.

### Confirmation

`tests/test_single_process.py` starts Quillfeed and fails if it opens a network connection to a database.
